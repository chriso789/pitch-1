# Architecture Decisions

- Marketing Audit reads explicitly tenant- and location-scoped contacts and an immutable integer-cent cost ledger; company spend and location leads are not combined into CPL, currencies are never mixed, and missing source evidence stays unattributed to prevent misleading performance claims.

- Final paid-in-full invoices generate a concise homeowner-facing Work Performed summary through `estimate-scope-narrative`; they never expose raw estimate line items as the invoice description.- Commercial budgets are created only by the `commercial_award_version` RPC from an approved estimate version's snapshot; awards and original budget values are immutable, and later changes must go through budget/change records, never edits to the estimate or originals.
- Commercial buyout packages link 1:1 to a commercial_bid_packages row; RFQ quotes enter leveling only via `commercial_record_rfq_quote`, vendors are reused from `vendors`/`contacts`, and `committed_cost` is never user-editable (owned by the commitment engine).
- Commercial commitment totals (PO/subcontract header values, budget pending/committed, buyout committed_cost) are derived only by `commercial_recompute_commitments` via triggers from the `commercial_commitments` view; approved commitment lines are locked and changes go through change orders.
- Commercial actual costs (budget actual_cost, PO/subcontract invoiced/paid/retainage) are derived only by `commercial_recompute_actuals` from approved vendor invoices and cost entries; approved invoices are locked and over-billing a commitment is blocked.
- Edge function CORS headers must allow `x-pitch-tenant`; the browser client sends it on every request for per-tab company selection, so the stock supabase-js cors import breaks browser calls.
- Customer invoice emails link to `https://pitch-crm.ai/invoice/:deliveryId`; the public viewer obtains short-lived PDF access through `email-api`, so storage hostnames never appear as customer-facing links.
- Review links on customer closeout pages are analytics-only: clicks and private feedback must never feed reward/qualification logic, and review copy is checked by a DB compliance trigger that blocks rating or incentive wording.
- Plan measurements go through the `MeasureEngine` adapter (`src/lib/plan-measure`), with PdfCraft WASM first and the JS fallback labelled in the UI. Quantities exist only against a calibrated per-sheet/viewport scale, and approval/export needs a verified scale (enforced by the `plan_measurement_guard` trigger), so no quantity ever comes from an assumed scale.
- PDF page operations (merge/split/reorder/rotate/crop/resize/stamps/bookmarks) go through `src/lib/pdf-pages/pageOps.ts` `compilePlan`, which re-inserts the base PDF's own page objects so forms, bookmarks and annotations survive; the source file is never modified and saves create new documents rows.
- PDF markups go through `src/lib/pdf-markup/markups.ts`: geometry is stored in PDF user space and written as standard annotations with appearance streams plus a `/PITCHMarkup` JSON entry for lossless re-editing; original page text is never rewritten (cover is a labelled overlay).
- Edited document versions are saved via `src/lib/pdf-pages/documentVersions.ts` (new `documents` row linked by `versions_root_id`); measurements carry to a new version only as drafts and only where user-space geometry is unchanged, otherwise the sheet is flagged in `metadata.measurement_reconciliation`.
- Existing-text editing goes through `src/lib/pdf-engine/contentTextEdit.ts`: in-place edits splice only the real Tj/TJ operator in the original font's own codes (glyphs proven present); move/restyle replaces that operator with an advance-preserving empty TJ and writes a new real text object, so the old text is removed, never covered. Outputs are reopened and checked, plus a pdf.js check that no other text moved; anything unproven stays read-only with a reason.
- Encrypted PDFs are opened for editing only via `src/lib/pdf-engine/decrypt.ts` (local qpdf WASM) and only when they open without a password, because pdf-lib cannot parse encrypted object streams; password-protected files stay blocked.
- Fill Forms writes actual AcroForm field values with read-back verification; appearance-font failures block output, and digital-signature fields remain unsupported to avoid false signing claims.
- PDF batch tasks run through `src/lib/pdf-batch/workflow.ts` `runWorkflow` (validated typed steps, bounded files/size, reopen check) and save each result via `saveDocumentVersion` with the steps recorded in metadata, so batches never overwrite originals and stay auditable.
- Image/Word→PDF conversion goes through `src/lib/pdf-convert/toPdf.ts`: JPEG/PNG are embedded unchanged, .docx is re-typeset from its structure (not a layout copy), and characters the standard fonts can't draw block conversion rather than being substituted; results save as new tenant-scoped documents.
- Subdirectories may have their own `AGENTS.md`; read it before changing files there.
